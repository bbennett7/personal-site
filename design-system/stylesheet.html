// Site structure

Proposed pages

Five pages at launch. The home does most of the work. Work, About, Notes, and Contact give visitors places to dig in. Notes is the optional engine for inbound — start empty, fill over time.

brynbennett.dev/ ├── / # Home — wordmark, intro, selected work, status ├── /work # Detailed case studies (3-4 selected projects) ├── /about # Career arc, what you build, what you care about ├── /notes # Essays / field notes — your longform engine │ └── /notes/[slug] # Individual essay └── /contact # Email, social, calendar link if relevant
brynbennett.dev/

Home

"Who is this person, and should I look closer?"

What's on it
  • Wordmark · hero scale
  • One-sentence positioning ("Senior fullstack engineer building AI product systems")
  • Two-sentence intro with bolded company names
  • Status line ("Open to new roles · Q3 2026")
  • Selected work — 3 most recent + impressive projects with one-line description
  • Footer · email + social
Launch Day 1 deliverable
brynbennett.dev/work

Work

"Show me the receipts."

What's on it
  • 3-4 case studies, longform
  • For each: problem, approach, outcome, technical decisions, what you'd do differently
  • Anchor projects: Mine, Quarry, Multi-peril coverage
  • Lighter index of older roles
  • Numbers where you have them (75% reduction, 95% recall, etc.)
Launch Day 1 deliverable
brynbennett.dev/about

About

"Is this person interesting to know?"

What's on it
  • Short narrative — career arc in 200-300 words
  • What you care about technically
  • Personal context — Laurel Canyon, side projects, music wall, gluten-free pursuits, etc.
  • Photo (optional but recommended)
  • Why the wordmark looks the way it does (1 sentence, easter egg energy)
Launch Day 1 deliverable
brynbennett.dev/notes

Notes

"Does this person think clearly in writing?"

What's on it
  • List of essays — title, date, 1-line preview
  • Each post is its own page at /notes/[slug]
  • Topics: AI engineering, system design lessons, career observations
  • Empty at launch is fine — fill 1/month over the next year
  • RSS feed for the technically-minded
Soon Empty page at launch · first essay within 30 days
brynbennett.dev/contact

Contact

"How do I reach this person?"

What's on it
  • Email (hi@brynbennett.dev)
  • LinkedIn · GitHub · X/Twitter (if applicable)
  • Optional: Cal.com link for "schedule a chat"
  • What you're open to ("recruiting, collabs, AI engineering questions")
  • Response time expectation ("usually within a few days")
Launch Can be 1 short page or part of footer
brynbennett.dev/talks (optional)

Talks

"What does this person speak about?"

What's on it
  • List of conference talks given
  • Each: venue, date, title, slides/video link
  • Add this once you've given your first talk (your career plan targets this in Q2-Q3)
Later Add when you have ≥1 talk
// Recommended build order

Ship sequence

Launch with home + work + about + contact. Notes empty but live. Talks page comes when there's a talk to put on it.

Week 1 ├── Buy brynbennett.dev (~$15) ├── Set up Cloudflare or Vercel hosting ├── Configure email (Fastmail / Google Workspace) └── Implement design system as React or static HTML Week 2 ├── Build / (home) — wordmark + selected work ├── Build /work — 3 case studies └── Build /about + /contact Week 3 ├── /notes scaffolding (empty, ready) ├── Add favicons (square ochre as primary) ├── Open Graph tags + meta └── SHIP Month 2+ └── First /notes essay (~30 days post-launch)
